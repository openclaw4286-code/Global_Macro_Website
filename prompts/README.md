# prompts/

매주 lesson을 발행하기 위한 프롬프트 모음입니다.
운영자(사이트 작성자) 본인이 사용하는 도구입니다.

## 폴더 구성

| 파일 | 역할 | 사용 시점 |
|---|---|---|
| `A-event-discovery.md` | 이번 주 다룰 만한 매크로 사건 후보 5개 추천받기 | 발행 사이클 시작 (5분) |
| `B-lesson-draft.md` | 정한 사건 + 각도로 인과 사슬과 본문 초안 생성 | 사건 결정 후 (5분 대기) |
| `C-causal-validation.md` | 초안의 인과 사슬을 다른 모델/세션에 비판적으로 검증 | 자신 없을 때만 (5분, 선택) |

각 프롬프트는 그대로 복사해서 Claude.ai 또는 ChatGPT(웹 검색 가능한 모델)에 던지는 형태입니다.

## 사용 흐름

전체 워크플로우와 매주 체크리스트는 [`../WRITING-GUIDE.md`](../WRITING-GUIDE.md)에 있습니다. 짧게 요약하면:

```
사건 결정 (A)  →  각도 정하기 (인간)  →  초안 생성 (B)  →  검수 (인간)
                                                             ↓
                                                     (자신 없으면 C)
                                                             ↓
                                                        발행 (인간)
```

A → B → C는 단지 도구 순서일 뿐, 매주 C까지 다 돌릴 필요는 없습니다.

## Phase 단계

이 폴더는 점진적으로 진화합니다.

### Phase 1 — 프롬프트만 (현재)
- 운영자가 프롬프트를 복사해서 외부 AI에 던지고, 받은 출력을 직접 정리해서 `lessons/{date-slug}.json`으로 저장
- 변환은 수작업 또는 텍스트 에디터 매크로로 처리
- 장점: 의존성 0, 즉시 시작 가능
- 한계: AI 출력 형식이 일정치 않아 매번 정리 비용

### Phase 2 — 변환 스크립트 (예정)
- `scripts/draft-to-lesson.ts` 추가: 프롬프트 B 출력 텍스트를 받아 `LessonSchema`로 검증된 JSON으로 변환
- `prompts/B-lesson-draft.md`의 출력 형식을 스크립트가 파싱 가능한 구조로 고정
- 검증 실패 시 어떤 필드가 빠졌는지 명확히 알려줌
- 발행 시점: 운영자가 프롬프트 B를 5회 이상 사용해 출력 형식의 변동성 패턴이 잡힌 후

### Phase 3 — 발행 자동화 (장기 검토)
- `scripts/publish-from-draft.ts`: draft → lesson JSON → git commit → push
- 사실 검증·각도 결정만 인간, 나머지는 명령 한 줄
- 도입 전에 30+ lesson 발행하며 사이클이 안정적으로 돌아간다는 증거가 필요

지금은 Phase 1입니다. 무리하게 자동화하지 않고, 발행 패턴이 보일 때 한 단계씩 올립니다.

## 자동화의 경계선 — 철학

| 자동 (AI/스크립트) | 인간 |
|---|---|
| 사실 수집·요약 | 어떤 사건을 다룰지 |
| 인과 사슬 초안 | "이 사건의 진짜 메시지가 뭔지" 각도 |
| 문장 작성 | 한 줄 통찰 |
| 형식 변환 (텍스트 → JSON) | 사실 검증·인과 검증·톤 검증 |
| 검증·빌드 | impact 분류의 보수성 판단 |

**경계선의 원칙**: AI가 잘하는 건 "그럴듯한 결과"를 빠르게 만드는 것. 거시 학습 사이트의 가치는 "정확하고 일관된 관점"에서 옵니다. AI에게 후자를 위임하면 사이트가 야후파이낸스처럼 됩니다.

따라서:
- AI는 **재료 제공자**이지 작성자가 아닙니다.
- 프롬프트는 본인 시간을 90분에서 30분으로 줄이는 도구이지, 본인을 대체하는 도구가 아닙니다.
- 사건 선택과 각도는 절대 위임하지 않습니다 — 그게 사이트의 정체성을 결정하기 때문입니다.

## 프롬프트 수정 시

각 프롬프트 상단에 변경 이력 섹션을 두고, 실전 사용 후 개선 사항을 기록하세요. 예시 (`B-lesson-draft.md`):

```
## 변경 이력
- v1.0 (초기): 기본 형식과 7가지 제약
- v1.1: 첫 실전 시도 후 3가지 제약 추가
```

작은 개선이라도 기록해두면 나중에 어떤 변경이 어떤 효과를 냈는지 되짚을 수 있습니다.
