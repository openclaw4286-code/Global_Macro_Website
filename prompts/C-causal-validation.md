# 프롬프트 C — 인과 사슬 교차 검증

선택 사용. 프롬프트 B로 만든 초안의 인과 사슬이 실제로 그럴듯한지
"다른 AI한테 비판적으로 봐달라"고 요청하는 프롬프트입니다.

같은 모델보다는 **다른 모델·세션**에 던지는 게 효과적입니다.
(예: 프롬프트 B를 Claude로 했으면 C는 ChatGPT, 또는 새 Claude 세션)

## 언제 사용하나

- 인과 사슬에 자신이 없을 때
- 사건이 정치적·논쟁적일 때 (편향 우려)
- 처음 다루는 카테고리일 때 (예: 처음 tech 카테고리 lesson 만들 때)
- 기존 lesson 5개 미만일 때 (학습 단계, 검증 빡세게)

매주 모든 lesson에 다 돌릴 필요는 없음. 시간 들여요.

---

## 프롬프트 본문 (복사해서 사용)

```
저는 매크로경제 학습 사이트의 lesson 초안을 작성했습니다. 인과 사슬이
정확하고 균형 잡혔는지 비판적으로 검토해주세요. 문제가 있으면 솔직하게
지적해주세요. "잘 만들어졌다"는 답을 듣고 싶은 게 아닙니다.

[검토할 lesson 초안]
{여기에 프롬프트 B로 만든 출력 전체를 붙여넣기}

[검토 항목 — 각 항목에 대해 OK / 우려 / 명백한 오류 중 하나로 평가하고 이유를 적어주세요]

1. trigger와 step 1 사이의 인과가 명확한가?
   - 이번 사건의 실제 흐름과 일치하는가, 아니면 일반 교과서 패턴인가?
   - 빠진 중간 단계는 없는가?

2. step들의 순서가 맞는가?
   - 시간 순서 또는 인과 순서로 정렬되어 있는가?
   - 동시에 일어난 일이 순차로 표현되어 있지 않은가?

3. outcomes의 impact 분류가 정확한가?
   - 각 outcome이 정말 그 방향(positive/negative/neutral)인가?
   - 같은 outcome인데 다른 시각에서는 반대 영향일 수 있는가?
   - 너무 단순화되어 있지는 않은가? (예: "전쟁 = 모두 부정적")

4. 빠진 outcome이 있는가?
   - 사건의 중요한 결과인데 다루지 않은 것?
   - 특히 "수혜자가 분명히 있는데 빠뜨린" 경우

5. 본문이 인과 사슬과 일치하는가?
   - 본문에서 주장하는 것과 사슬의 논리가 모순되지 않는가?

6. 한 줄 통찰이 진짜 통찰인가, 아니면 사실 진술인가?
   - "X가 일어났다"가 아니라 "X가 일어나는 이유는 Y라는 원리 때문이다" 형태인가?

7. 다른 시나리오와 너무 비슷하지 않은가?
   - 매크로경제 lesson은 다양해야 합니다. 비슷한 사건의 비슷한 사슬을 반복하면
     사이트가 지루해집니다.

8. 한국 사용자 관점에서 잘못된 가정은 없는가?
   - 미국·유럽 시각이 한국에 그대로 적용되는 것처럼 쓰여있지는 않은가?

[종합 평가]
- 발행 가능 / 수정 후 발행 / 재작성 필요 중 하나로
- 가장 우려되는 부분 1~2개
- 개선 제안

[출력 형식]
검토를 표 형태나 번호로 정리해서 주세요. 단순한 칭찬은 빼주세요. 비판이 본 목적입니다.
```

---

## 검토 결과를 받은 후

검토에서 "수정 후 발행" 판정이 나왔을 때:
- 우려 사항 2개 이상이면 본인이 직접 사실 재확인 후 수정
- 1개 이하면 프롬프트 B 세션에 돌아가서 "X 부분을 이렇게 수정" 요청

검토에서 "재작성 필요" 판정이 나왔을 때:
- 사건 자체를 다시 생각해보세요. 이 사건이 진짜 lesson 가치가 있는지.
- 또는 각도를 바꿔서 프롬프트 B를 다시 시작.

검토 AI도 틀릴 수 있음. 그래도 본인이 검수할 항목을 늘려주는 안전장치 역할.
